**NexusUserTest** — это современное веб-приложение для организации и проведения тестирования пользователей. Проект реализует полноценную экосистему, включающую пользовательский интерфейс, административную панель и серверное Web API. Архитектура приложения построена по принципам Clean Architecture с чётким разделением на предметную область, прикладную логику, инфраструктуру и представление.

---

## 🚀 Основные возможности

- 👥 **Управление пользователями**: регистрация, аутентификация и ведение профилей.
- 👥 **Управление группами**: создание групп и распределение участников.
- 🎓 **Специализации**: привязка пользователей к профессиональным или учебным специализациям.
- 📚 **Темы тестирования**: гибкая настройка категорий и тем для тестов.
- 📝 **Конструктор тестов**: создание и редактирование вопросов с различными типами ответов.
- ⚙️ **Настройка параметров тестирования**: время, проходной балл, количество попыток и т.д.
- 🛡️ **Разделение ролей**: изолированные интерфейсы для обычных пользователей и администраторов.
- 🔐 **Безопасность**: аутентификация и авторизация на основе JWT (JSON Web Tokens).
- 📡 **Web API**: серверная обработка всех запросов с интерактивной документацией Swagger.

## 🏗 Архитектура проекта

Решение `NexusUserTest.sln` организовано в соответствии с принципами Clean Architecture:

```text
src/
├── Client/
│   ├── NexusUserTest.Client/       # Точка входа и хостинг Blazor-приложения
│   ├── NexusUserTest.Admin/        # Компоненты административной панели
│   ├── NexusUserTest.User/         # Компоненты пользовательского интерфейса
│   └── NexusUserTest.Shared/       # Общие клиентские компоненты, DTO и сервисы
│
├── Server/
│   ├── NexusUserTest.WebApi/       # Точка входа API, контроллеры, настройка DI и middleware
│   ├── NexusUserTest.Application/  # Прикладные сервисы, сценарии использования, валидация
│   ├── NexusUserTest.Domain/       # Доменные модели, интерфейсы репозиториев, константы
│   └── NexusUserTest.Infrastructure/ # Реализация репозиториев, EF Core контекст, миграции
│
└── NexusUserTest.Common/           # Кросс-проектные утилиты, расширения и общие типы
```

### Назначение слоёв

- **WebApi** — запуск серверного приложения, обработка HTTP-запросов и настройка API.
- **Application** — прикладные сервисы, валидация и реализация сценариев работы с данными.
- **Domain** — модели предметной области и доменные абстракции.
- **Infrastructure** — доступ к PostgreSQL через Entity Framework Core, репозиторий, аутентификация и авторизация.
- **Client** — веб-приложение на Blazor с интерактивным серверным рендерингом.
- **Admin** — компоненты административного интерфейса.
- **User** — компоненты пользовательского интерфейса.
- **Shared** — общие клиентские компоненты, сервисы и механизмы взаимодействия с API.
- **Common** — общие типы, используемые несколькими проектами.

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/KabanovAV/NexusUserTest.git
cd NexusUserTest
```

### 2. Настройка конфигурации

Перед запуском необходимо настроить конфигурационные файлы серверного и клиентского приложений.

Укажите параметры подключения к PostgreSQL в конфигурации Web API:

```json
{
  "ConnectionStrings": {
    "PostgreConnection": "Host=localhost;Port=5432;Database=NexusUserTest;Username=YOUR_USERNAME;Password=YOUR_PASSWORD"
  }
}
```

Также необходимо настроить секцию `JwtSettings`, используемую для проверки JWT-токенов. Она должна содержать параметры издателя (`Issuer`), аудитории (`Audience`) и ключа подписи (`Key`).

Значения JWT должны соответствовать конфигурации, используемой при выдаче токенов.

Для локальной разработки можно использовать `appsettings.Development.json`. Не добавляйте пароли, ключи подписи и другие секреты в репозиторий.

Клиентскому приложению также требуется конфигурация, соответствующая его настройкам и адресу Web API.

### 3. Восстановление зависимостей

```bash
dotnet restore NexusUserTest.sln
```

### 4. Сборка решения

```bash
dotnet build NexusUserTest.sln
```

### 5. Запуск Web API

```bash
dotnet run --project src/Server/NexusUserTest.WebApi/NexusUserTest.WebApi.csproj
```

### 6. Запуск веб-приложения

В отдельном терминале выполните:

```bash
dotnet run --project src/Client/NexusUserTest.Client/NexusUserTest.Client.csproj
```

Адреса приложений и дополнительные параметры запуска определяются конфигурацией и профилями запуска проекта.

> Перед первым запуском проверьте, что база данных создана, схема актуальна и сервер настроен на корректное подключение к PostgreSQL. Порядок применения миграций зависит от текущего состояния проекта.

## Документация API

В проекте используется Swashbuckle для интеграции Swagger. Если Swagger включён в конфигурации и настройках запуска, документация API будет доступна по адресу `/swagger` на соответствующем адресе Web API.

## Логирование

Для логирования используется Serilog. Конфигурация логирования загружается из настроек приложения. Серверный проект также содержит каталог `Logs` для лог-файлов.

## Статус проекта

Проект находится в разработке. Фактическая доступность отдельных сценариев, включая обработку результатов тестирования, зависит от текущей реализации.
